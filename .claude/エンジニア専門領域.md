# エンジニア専門領域・C列職種名一覧

エンジニア求人の **C 列（職種名）** は、Indeed の審査エラー（「職種名が不明確」「職種名以外の情報が含まれている」など）を避けるため、**以下の固定書式**で生成する。

## C 列の固定書式（エンジニアのみ）

```
【未経験可】フルリモート〇〇エンジニア
```

- **冒頭の `【未経験可】` と `フルリモート` は固定**。並べ替え・省略・別表現への変更は不可。
- **末尾は必ず `エンジニア`** で締める。
- **〇〇 の部分**は、後述の「〇〇 に入る一覧」から **1 つだけ** 選ぶ（複数並べたり `／` `｜` で連結したりしない）。
- 全体で 30 字前後を維持。
- iRup・UPBUILD・Xedge **全社のエンジニア求人で統一**。
- この書式は `.claude/列定義.md` の「C 列：【キャッチコピー】普通の文章一文スタイル」の **エンジニア向け具体化版**にあたり、エンジニア求人ではこちらが優先。

### 良い例

- `【未経験可】フルリモートAWSエンジニア`
- `【未経験可】フルリモートクラウドエンジニア`
- `【未経験可】フルリモートセキュリティエンジニア`
- `【未経験可】フルリモートデータベースエンジニア`
- `【未経験可】フルリモートReactエンジニア`

### 悪い例（Indeed に弾かれる／旧書式）

- `【未経験可】フルリモート可能なインフラ／保守運用エンジニア`（〇〇 に `／` を含む・職種名内に複数領域）
- `【未経験可】単価開示100％のAWSエンジニア`（〇〇 以外の訴求が混入）
- `【未経験可】フルリモート可能なAWS／インフラエンジニア`（〇〇 の連結）
- `【未経験可】AWSエンジニア`（`フルリモート` を省略）

## D 列「職業カテゴリー」の有効値（Indeed 一括アップロード）

D 列は **Indeed の職業カテゴリーの「リーフ名」完全一致のみ**受け付ける（一括アップロード検証で弾かれる）。複数指定は `、` 区切り。エンジニア求人で使える **IT カテゴリーの有効リーフ**は以下（2026-05 時点、`/bulkupload/occupation-reference` で確認）:

- `システムエンジニア` は **親グループでリーフではない**ため D 列に書くと弾かれる（`web/オープンSE` 等のリーフを使う）。`プログラマー` も同様に親グループ。

| 有効リーフ（D 列にそのまま書ける） |
| --- |
| `フロントエンドエンジニア` |
| `サーバーサイドエンジニア` |
| `データベースエンジニア` |
| `ネットワークエンジニア` |
| `セキュリティエンジニア` |
| `データエンジニア` |
| `DevOpsエンジニア` |
| `QA/テストエンジニア`（「QAエンジニア」「テストエンジニア」単独は不可。この1語で表す） |
| `保守/運用/サポートエンジニア` |
| `社内システムエンジニア` |
| `SRE（Site Reliability Engineer）` |
| `アーキテクト` |
| `データサイエンティスト` / `データアナリスト` |

**弾かれた実績（使わない → 置換）**:
- `インフラエンジニア` → `DevOpsエンジニア` または `ネットワークエンジニア`／`サーバーサイドエンジニア`
- `アプリケーションエンジニア` → `サーバーサイドエンジニア`
- `QAエンジニア`・`テストエンジニア` → `QA/テストエンジニア`
- `システムエンジニア`（親グループ）→ `サーバーサイドエンジニア` 等のリーフ

C 列で選んだ〇〇 に応じた D 列の目安: AWS/クラウド/インフラ→`サーバーサイドエンジニア、ネットワークエンジニア、DevOpsエンジニア`／セキュリティ→`セキュリティエンジニア、ネットワークエンジニア`／DB・データ基盤→`データベースエンジニア、データエンジニア`／言語FW（Python/Go 等）→`サーバーサイドエンジニア、データベースエンジニア`／QA→`QA/テストエンジニア、サーバーサイドエンジニア`。

## 運用ルール

- C 列の生成時、**まず本ドキュメントの〇〇一覧から 1 つ選ぶ**。リスト外のワードを使いたい場合は、本ドキュメントに追記してから使う（その場限りで増やさない）。
- 複数件まとめて生成するときは、**できるだけ別のカテゴリー・別のワードを散らす**（10 件全部 `AWS` などにしない）。
- AT／AU 本文では「技術スタック早見表」のサブ領域を素材として組み合わせる。C 列のワードと AT 本文のテーマが整合すること（例: C 列が `セキュリティ` なら AT 本文も SOC／SIEM／脆弱性診断などセキュリティ寄りに）。
