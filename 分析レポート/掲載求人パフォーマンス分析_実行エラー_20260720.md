# 掲載求人パフォーマンス分析 ― 実行エラー（2026-07-20）

## 結論
3社（iRup / UPBUILD / Xedge）のパフォーマンス分析は **未実行**。Indeed 採用企業ダッシュボードへのログインが **Google 2段階認証（2FA）でブロック**されたため、データ取得に到達できなかった。スケジュール実行のためユーザー不在で、2FA を突破できない。

## 隔週判定
- ISO 週番号 = **30（偶数）** → 実行対象週。スキップ条件には該当せず、続行を試みた。

## どこで止まったか（ログイン経路）
1. `https://employers.indeed.com/analytics/report-jobs-campaigns` にアクセス → ログイン画面へリダイレクト。
2. メールアドレス `****@gmail.com` を入力 → **Google アカウント保護（SSO）**へ。パスワード直接入力の欄はなく「Googleで続ける」経由。
3. Google OAuth: メール確認 → パスキー要求 → 「別の方法を試す」→「パスワードを入力」を選択し、`.env` のパスワードで認証成功。
4. **その直後に「2段階認証プロセス」画面**。提示された選択肢は次のいずれもユーザーの物理デバイスが必要:
   - パスキーを使用
   - 1回限りのセキュリティコード（別デバイスのパスキー/セキュリティキー）
   - スマートフォン/タブレットで「はい」をタップ（端末プッシュ承認）
   - 電話番号 •••-••••-••45 へ確認コード（※「より安全なオプションがあるため使用できません」と表示され **無効化**）
5. いずれも自動化不可のため、スキルの規定（「2段階認証・想定外画面が出たら停止して通知」）に従い停止。

## 影響
- iRup・UPBUILD・Xedge いずれも **アナリティクス未取得**。CTR/CVR 算出・レポート・ドキュメント改善プロンプトは今回生成していない。

## 復旧のための推奨アクション（ユーザー対応が必要）
1. **一度ユーザー本人が手動でログインし 2FA を通す**。ブラウザ/プロファイルにセッション（Cookie）が保持されれば、以降のスケジュール実行は 2FA を再要求されずに通る可能性が高い。
2. もしくは、この採用アカウントの Google で **「信頼できるデバイス」登録**や、自動化用に 2FA を通した状態のプロファイルを用意する。
3. 電話番号 (•••45) への SMS が Google 側で無効化されているため、SMS コードを読み取れる連携があっても現状は選べない。まずは手動セッション確立が最短。
4. 次回の隔週実行（ISO 週が偶数の週）までにセッションを確立しておけば、再試行で取得できる見込み。
